# lunar02 — 字库 + 计算组架构

> 一句话：训练一个「小而会算的计算组 + 巨大但稀疏查询的知识字库」的语言模型。
> 推理时字库放在 SSD / 内存里，计算组每生成一个 token 只取回几十到几百行知识条目，
> 从而用消费级硬件获得超大总参模型的知识容量，定位是边缘推理与小显存环境。

本 README 自包含，面向没有历史上下文的读者。前半讲思路，后半讲实验
结果、已验证/未验证的边界、待决问题。所有数字均为实测值，出处见
文件索引。标注「估算」的数字除外。

## 动机

1. 观察到顶尖 MoE 总参极大、单次激活 modest（量级举例：总参
   2800B、激活约 30B）。总参 ≈ 知识，激活 ≈ 运用。
2. 消费级推理的瓶颈是带宽，不是算力。
3. MoE 的专家个体太大，交换粒度粗，受限于搬运整块专家的带宽；
   字库把交换单元打到 token 级细粒度，单发随机读即可喂上。

=> 把 MoE 的「激活参数 / 总参数」改写成「运用 / 知识」：运用放在
显存里的计算组，知识摊在便宜的存储（内存 / SSD）里。

## 架构（当前实现）

- 计算组：标准 decoder-only Transformer（探针阶段为 4 层、
  d_model=128 的小模型；终局目标 A2B 激活量级）。
- 字库层：Product Key Memory 风格定址。两张各 √N 行的键表组合出
  N 个地址；查询向量由 hidden state 算出（非 token id 直接定址），
  劈成两半分别对两张键表取 top-8，拼出 64 个候选再选最终 8 个；
  多头（4 头）共享一张 N × d_v 值表；检索结果经门控残差注入。
- 存储层级设计：键表永驻 RAM（2√N 行，打分永不碰盘）；热条目
  （Zipf 前约 1%）驻 VRAM；字库主层设计驻 DRAM（128GB 三值约
  640B 参数）；冷层驻 SSD（连续大表 + 4KB 对齐行，memmap 友好）。
- 训练：字库全部可训练、与本体联合训练（无冻结索引）；规模化
  训练预留 BTM 式方案（冻结共享主干、分域分训 FFN 条目、轻训
  路由）作为对冲。
- 终局压缩：字库三值化（约 1.58 bit/参数），把每 GB 存储的
  知识密度从 BF16 的约 0.5B 参数推到约 4B（三值质量税尚未实测，
  见「已验证 / 未验证」）。

## 与现有工作的关系（诚实清单）

- PKM 乘积键（Lample et al. 2019）：字库层的直接前身，当前实现
  即 PKM 风格，不是全新发明。
- RETRO（DeepMind 2021）/ kNN-LM / Memorizing Transformer：检索
  增强与外部记忆一脉，「参数换检索」已有先例。
- LLM-in-a-Flash（Apple 2023）/ PowerInfer：冷热权重分层卸载到
  闪存的先例。

本项目相对增量：把稀疏可训练记忆作为模型的「知识层」主规模轴
（而非辅助组件）、面向消费级盘的 token 级交换粒度、规划按层混布
两种定址方式。

两条自有发现：

1. 两阶段 top-k（两侧各取 k，再对 k² 组合取 k）在加法打分下是
   精确搜索而非近似（有反证证明，欢迎复核）。
2. 可微定址的地址在 forward 中途才确定，因此 SSD 读取无法提前
   预取——这是存储层设计的硬约束；「按最近 token 定址」的哈希式
   方案地址在计算前已知、可预取，是其存在价值，两条支线可能按层
   混布。

## 已完成的实验

### 探针 #0（TinyStories 小规模验证）

设置：4 层 d=128，GPT-2 分词器，30M token 池固定种子采样，每实验
训练 1024 万 token（10000 步 × batch 8 × 序列 128），AdamW，主网络
LR 3e-4 / 值表 LR 为其 5 倍，关键配置跑种子 1/2/3。指标为「最后
1000 步平均验证 loss」（40 个验证点算术平均）。

最终结果（验证 loss，越低越好）：

| 配置 | 总参 / 激活 | 验证 loss |
|---|---|---|
| A 纯基线（7.24M 全激活） | 7.24M / 7.24M | 2.57554 |
| B 加宽 dense FFN | 15.80M / 15.80M | 2.57216 |
| C-16K 字库 | 9.44M / 7.34M | 2.56421 |
| C-65K 字库 | 15.76M / 7.37M | 2.57027 |
| **C-262K 字库** | 40.99M / 7.44M | **2.52234** ← 全场最好 |
| C-1M 字库 | 141.79M / 7.57M | 2.52880 |

多种子（种子 1/2/3，末 1000 步平均）：

| 配置 | 验证 loss |
|---|---|
| A | 2.64357 ± 0.00750 |
| C-65K | 2.63014 ± 0.01194 |
| C-262K | 2.60628 ± 0.00731（三个种子全部优于 A） |

读法：

- 等总参对比：C-16K（9.4M 总参）打赢 B（15.8M 全激活 dense），
  C-262K 把差距拉大——稀疏记忆在玩具尺度有参数效率优势。
- 字库不是越大越好：1M 档未超过 262K 档，饱和点归因未定
  （候选解释：数据量不够 / 单格容量太小）。
- 激活参数全部在 7.3~7.6M，总参从 9.4M 到 141.8M——「激活 modest、
  总参巨大」的形态成立。

关键消融：

- 字库置零：loss +0.19；随机替换地址：loss +0.24（比置零更差）。
  => 模型依赖的是「查对地址 + 内容正确」，不是拿字库输出当噪声。
- 累计格子使用率 70.8%（262K 档）/ 44.4%（1M 档），无全局塌缩。
- 循环（第 3/4 层共享权重跑 3 圈）：稳定有害，且削弱字库收益约
  40%；该负结果不构成对隐式推理的否定（任务无多跳需求）。
- FFN 加宽：0.5× → 1× 改善 0.082，继续加宽回落。探针 #1
  （见 FFN_LR_PROBE_REPORT.md）已对该现象做了欠训练假设检验。

### 存储微基准 #1（NVMe，Windows 无缓冲直读，冷路径）

- QD1 单发 4KB 随机读：mean 82.6µs（p50 80.1 / p99 164.1 /
  max 1055.9），QD1 有效带宽约 49MB/s——单发随机读是延迟绑定。
- 最悲观串行模型（32 读/token、逐个等待）：2.64ms/token，
  折合 379 tok/s。32 次取格对应本设计 4 头 × top-8。
- 结构推论：单流推理吃的是 IOPS 与延迟，不是带宽——20 tok/s
  的目标仅需约 640 IOPS / 2.6MB/s；层内 32 次取格相互独立，应
  并发发射（并发批约 165µs vs 串行 2.64ms）。
- 口径注意：此盘为旗舰级原装盘，数字作天花板用；QD1 延迟跨
  TLC 盘大致可移植，高队列下的并发天花板不可外推，待中端参考盘
  重测。

### 探针 #2（值表形态：胖条目 vs 多而瘦，TinyStories）

设置：值表预算精确拉平到 33,554,432 参数——A：N=262144×d_v=128；
B：N=65536×d_v=512；LR {3e-4,6e-4} × 种子 {1,2,3}，固定 20,000 步。

裁决：**黄（等价）**。best(A)−best(B) = 0.00331，远在 0.01 阈值内。

读法：单格容量与寻址分辨率都不是主要杠杆，L 号的 d_v/N 配比按
系统账（访存字节、寻址与候选组合开销）选，不按精度差选。B 累计
使用率 78.5% 无塌缩；B 每 token 读 4 倍字节但吞吐反而略高（N 小则
键表打分少）。完整报告：VALUE_SHAPE_PROBE_REPORT.md。

### 探针 #3（0.5B 规模探针，FineWeb-Edu 152M token）

设置：计算组 d_model=1024×36 层（三组的激活参数恒为 5.08 亿），
字库层第 18 层后注入、4 头 top-8、d_v=512；N=4M 档值表 20.5 亿
参数常驻 CPU，命中行稀疏反传（峰值显存仅 10.8GB/卡）。数据冻结：
训练 152M token、held-out 同域/域外各 4M，重叠率 0；200 道闭卷
事实 QA 经用户终审冻结。LR {3e-4,6e-4} × 网格种子 {1,2} +
best-lr × 确认种子 {3,4}，每组 4 种子报均值±样本标准差。

结果（best lr 均为 3e-4）：

| 组 | 总参/激活 | held-out PPL | 域外 PPL | QA 精确率 | 字库累计使用率 |
|---|---:|---:|---:|---:|---:|
| dense | 5.06 亿/5.06 亿 | 313.5 ± 20.1 | 342.3 ± 29.7 | 0 | — |
| N=1M | 10.2 亿/5.08 亿 | 311.1 ± 26.7 | 336.2 ± 32.4 | 0 | 8.2% |
| **N=4M** | **25.6 亿/5.08 亿** | **56.3 ± 1.7** | **67.4 ± 2.2** | 0 | 4.9% |

裁决：**绿**。增益比 r = (311.1−56.3)/(313.5−311.1) ≈ 108（阈值 0.5）。
（后续已被探针 #4 修订，见下一节。）

诚实声明：dense/N=1M 按设计只训练 38M token，N=4M 吃满 152M——
这是「字库让计算组消化 4 倍数据」的系统级联合胜利，不是同数据
单挑。归因对照（探针 #4）已落地：dense@152M 达到 PPL 56.07，与
N=4M 的 56.26 统计等同——#3 裁决据此修订为「数据 scaling 胜利」，
254.8 PPL 增益全部来自 4 倍数据，字库在该规模-数据组合下 PPL 收益
为零。两条边界如实记录：QA 闭卷桶全体精确率 0（0.5B 闭卷
冷知识超出能力边界，零结果也是结果）；N=4M 累计格使用率仅 4.9%，
表远未饱和。环境与冒烟：SCALE_SMOKE_REPORT.md；
结果：runs/scale_probe/{summary.csv, verdict.json, curves.png}。

### 探针 #4（dense@152M 等训练算力对照，#3 归因裁决）

设置：与 #3 dense 组逐参数一致（args.json 级 diff 为空），唯一变化
train_tokens 38M→152M；LR {3e-4,6e-4} × 种子 {1,2,3,4} 共 8 runs，
best-of-grid 四种子报均值±样本标准差；三桶同口径。

结果与裁决：

| 组 | held-out PPL | 域外 PPL |
|---|---:|---:|
| dense@38M | 313.5 ± 20.1 | 342.3 ± 29.7 |
| **dense@152M** | **56.07 ± 1.38** | **60.57 ± 2.06** |
| n1m@38M | 311.1 ± 26.7 | 336.2 ± 32.4 |
| n4m@152M | 56.26 ± 1.66 | 67.42 ± 2.17 |

**s = (313.5−56.07)/254.8 = 1.010 ≥ 0.85 → 数据主导：#3 降级为
「数据 scaling 胜利」，字库贡献另议。** dense@152M 与 N=4M@152M
在 held-out PPL 上统计等同；域外 PPL dense 反而低约 7（约 3σ，
倾向性信号待复核）。完整报告与机检证据：DENSE_CONTROL_REPORT.md。

读法：这把项目问题从「字库有没有用」精确化为「字库收益的存在条件
是什么」（候选：更大 N×更多数据、多层注入、预取友好定址、训练配方）。
QA 桶因基座零样本闭卷全体为零，「字库存知识」需 few-shot 新口径重测。

### 探针 #6–#9（2026-11-18 ~ 11-21，全部红；负面结果合集）

这四条是连续的：先用埋事实微基准测「送达」，再用白盒解剖找病根，再试小修，最后换
「把已训 FFN 抽出来当字库」的移植路线。四条全部为红，合起来给出当前最硬的结论：
**字库的失败不在寻址、不在振幅，而在「内容怎么进去」；而「从已训模型里切一块 FFN」
也救不了它，因为 FFN 的输出本身就弥散。**

| 探针 | 设置 | 结果 | 裁决 |
|---|---|---|---|
| #6 埋事实微基准 | 2000 条合成事实，曝光 {1,5,20,100}，pair 对抗打分（表面匹配，chance 50%） | 字库臂 f(曝光) 平：47.8/47.4/46.6/54.6%；**值表置零/随机置换后逐位一致**；同时 dense 臂 100 次曝光也只有 57.6/58.2% | 红 |
| #7 白盒解剖 | T0 存入 / T0a 接线 / T1 送达 / T3 寻址 / T2 三变体 | 值表 delta 均值仅为行尺度 0.15%（随机游走）；冻结侧网则表学不进；共训时侧网可训也只入表 2.4pt | 红（病根=写入机制） |
| #8 小修 A/B | A1 振幅修复 ×10、A2 重建辅助损失，LR×种子全格网 | ablate_diff@100 全部落在 1.2–2.8pt，低于 3pt 红线；v3r 复现 1.8pt（存档 2.4pt，带内） | 红 |
| #9 移植（0.5B） | 第 18 层 FFN（F=4096, GELU）oracle 稀疏重建 + 检索 + 乘积键 | 25% 读宽才到 2.1%；余弦检索集配真门值与 oracle 几乎重合，**softmax 门控崩溃**；乘积键 64×64 只用到 24% 格 | 红 |
| #9 移植（14B） | Qwen3-14B（F=17408, SwiGLU）第 20 层，供体自身隐状态 | 23.5% 读宽仍差 30.7%，47% 才到 13.7%；0.5B→14B 岭回归桥验证误差 93.5%（且实验欠定） | 红 |

**两条可直接引用的定量结论**（详见 `TRANSPLANT_NEGATIVE_REPORT.md`）：

1. **FFN 稀疏度随规模下降**：同为 25% 读宽，0.5B 误差 2.1%、14B 误差 30.7%（约 15×）。
   「大模型 = 可切开的稀疏专家」这个直觉，在我们测到的两个尺度上是反的。
2. **接口宽度是硬约束**：要把一层 FFN 的信息保住，0.5B 尺度需每 token 触碰约 1024 个条目；
   现有设计是 4 头 × top-8 = 32 次读。任何 1:1000 激活比的设计都必须先回答读宽度怎么放大。

## 已验证 / 未验证（边界声明，重要）

已验证（多种子 + 双消融 + 数学证明，三证据互证）：

1. 稀疏字库可被学习、模型确实在使用检索内容。
2. 等总参下稀疏胜稠密（玩具尺度成立，外推未验证）。
3. 字库收益不随 N 单调增长（262K 档饱和于 10M token 数据量）。
4. 两阶段 top-k 在加法打分下精确（证明）；可微定址无法预取
  （结构性事实）。
5. 单流延迟账：最悲观假设 379 tok/s，为 20 tok/s 下限目标的
   19 倍。
6. 0.5B 激活不变（5.08 亿）：喂满 152M token 可把 held-out PPL 从
   313 压到 56；但 dense 与 N=4M 字库在此规模-数据组合下 PPL 统计
   等同（探针 #3+#4，s=1.010）——数据 scaling 成立，字库 PPL 收益为零。
7. 20 亿参数值表 CPU 常驻 + 命中行稀疏训练在工程上成立：
   峰值显存 10.8GB/卡、吞吐 4.5~4.8k tok/s（RTX 3080 @250W）。
8. 被动梯度写入不成立（探针 #6/#7/#8）：事实消融逐位无感、值表更新停在
   随机游走量级、振幅修复与重建辅助损失都救不回来。负结果，但证据链完整。
9. FFN 不是稀疏键值表，且稀疏度随规模下降（探针 #9）：0.5B 25% 读宽误差 2.1%，
   14B 23.5% 读宽误差 30.7%。据此，「从已训大模型切一块 FFN 当字库」这条路关闭。

未验证（不得对外宣称）：

1. 字库收益的存在条件：0.5B×152M 下 PPL 收益为零（探针 #4，
   s=1.010）；何种规模/数据/配方下字库开始兑现收益，是当前最大
   未决问题。262K 饱和归因仍无定论（数据饥饿 vs 单格 128 维太小）。
2. SSD 端到端：推理引擎未写；高队列 IOPS 天花板未测；多级
   存储（VRAM/DRAM/SSD）分层未实现。
3. 三值化质量税：全部容量账的承重墙，未实测。
4. 计算组「运用知识」的瓶颈归因：探针 #9 倾向支持「接口宽度」（25% 读宽才到
   2% 误差，现有 4 头×top-8=32 读），但「同质容量」未被排除——两者未做正交对照。
5. 能力评测闭环缺失：loss 改善不能证明能力对标。
6. 按构造写入（哈希/实体 id 定址 + 只学读路径）是否能送达事实：未测，
   这是目前唯一还没被证否的存储侧命题。

## 当前瓶颈与下一步

1. 字库 PPL 收益在 0.5B×152M 为零（探针 #4，s=1.010）；探针 #6–#9 进一步把
   病根收敛到「内容怎么进去」，并关闭了「从已训模型切 FFN」的捷径。下一个
   决策点收窄为两条：①按构造写入（哈希/实体 id 定址 + 只学读路径）能否送达
   事实；②在 dense 能饱和的小尺度战场（约 20M 参数）上，字库能否在等激活
   参数下赢 dense。两条都不需要 0.5B 级算力。
2. 数据管线按终局标准一次建成：10B 级需 30~60B unique token；
   外推到 1T 级条目需 3~6T unique token——数据（不是 SSD）才是
   字库容量的真实上限。
3. 诚实的差距声明：训练算力（巨型模型约 10^25 FLOPs 对单次
   上限约 4B dense，差 3~4 个数量级）、大规模稀疏训练稳定性、
   知识可外放而程序性技能不可外放（推理/代码/数学住权重里），
   是三堵尚未翻过的墙。「对标万亿模型」当前是外推问题不是
   目标：叙事拐点为 ①L 号 1:1000 激活比成立、②字库收益 scaling
   斜率为正。

## 关键账速查

- 目标速度下限 20 tok/s（人希望更快；20 是可用线不是目标线）
- 汇率：32 格并发一批约 165µs；串行每读 82.6µs
- 估算：100 tok/s 时每 token 约可承担 1700 次并发取格（已扣
  L 号计算组算力约 0.2~1ms，此数为估算）
- 终局 L 号形态（规划）：计算组 A2B 三值 + 字库主层 300~600B
  参数（DRAM）+ SSD 冷层；激活:总参 ≈ 1:1000，为现有 MoE
  （约 1:90）的十倍开外——此为规划目标，非已实现。
